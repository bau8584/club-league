# 동호회(club-league) → 학교(school-league) 이식 계획서

> **목적**: club-league에서 다듬은 사용자 경험(UX)·인터페이스(UI) 개선을 학교용 리그에도 선별 이식한다.
> **원본(소스 오브 트루스)**: `D:\다운로드\club-league` · **대상**: 이 저장소(`D:\다운로드\school-league`)

---

## 이 문서를 사용하는 방식 (작업자/AI 공통 규칙)

1. **항목 단위로 진행한다.** 아래 체크리스트를 위에서부터 하나씩 본다.
2. **무턱대고 복사하지 않는다.** 학교 리그는 동호회와 도메인이 다르다:
   - 학생은 **학년/반/번호**로 식별(동호회는 이름/닉네임/레벨).
   - **키오스크 화면 잠금(LockGate)** 사용 — 동호회는 제거함.
   - **개인 코드(PIN)·StudentCardSettings** 사용 — 동호회는 신뢰모델(자율)로 제거함.
   - **자율 참가/멤버 승격·강등, 레벨 체계** 없음 — 동호회 전용.
3. 각 항목마다 **① 학교 맥락에 맞는지 판단 → ② 사용자에게 "이거 적용할까요? 이렇게 바꾸려는데 괜찮나요?"라고 먼저 묻고 → ③ 승인 시에만 수정**한다.
4. 학교 고유 요소(학년/반, LockGate, PIN)를 **삭제·훼손하지 않는다.** 동호회처럼 지우자고 임의 결정하지 말 것. 필요하면 사용자에게 확인.
5. 적용 후에는 항상 `npx tsc --noEmit` + `npm run build`로 검증.
6. 상태 표기: `[ ]` 미착수 · `[~]` 부분/검토중 · `[x]` 완료. 적용하면서 갱신.

## C. 관리자(Admin) UX — 선별 이식

### C1. 휴면 감점 시스템 → 독립 탭 (이번 세션 신규) [ ]
가장 최근 대규모 작업. 동호회에서:
- 관리자 패널에 **"휴면 감점" 전용 탭** 신설(설정·실시·내역 통합).
- **티어별 감점값 통일 버그 수정**: 보너스/패널티 저장 함수가 단일 `decayAmount`로 decaySettings를 덮어쓰던 문제 제거 → 티어별 값 유지.
- **기본값**: 시스템 켜면 골드/플래티넘/다이아 자동 선택.
- **자동 → 수동 전환**: 자동 감점은 `lastMatchDate` 미로드로 사실상 동작 안 했음. `matches`에서 최근 활동일을 직접 계산하는 **수동 "실시" 버튼 + 미리보기 + 확인** 방식으로 교체.
- **전용 로그 테이블 `decay_log` + RPC `apply_dormancy_decay`**(원자적 차감+기록), 탭에서 내역 열람.
- **관련 파일(club)**: `src/components/league/admin/DecayManager.tsx`(신규), `src/lib/league-store.ts`(previewDormancyDecay/applyDormancyDecay/fetchDecayLog + saveLeagueSettings 클로버 제거), `src/services/league-api.ts`(apiApplyDormancyDecay/apiFetchDecayLog), `src/lib/settings-migration.ts`, `db/migrations/2026-06-26_decay_log.sql`, `db/schema/club_schema.sql`.
- **학교 적용 판단**: 학교는 커밋 `bebff68`에서 **"자동 휴면 감점 복구"**를 한 이력 → 학교는 **자동 방식을 유지·선호할 수 있음.** 동호회처럼 수동 전환을 강요하지 말 것. 단, **티어별 통일 버그 수정**과 **로그 열람 창**은 자동/수동과 무관하게 가치 큼.
- **DB 주의**: `decay_log` 테이블·RPC는 학교 스키마(`students`/`classes` 명칭)에 맞춰 컬럼·권한 함수(`is_class_teacher` 등)를 재매핑해야 함. 마이그레이션 적용 필요.
- **확인 질문**: "학교 휴면 감점을 ①티어별 버그만 고칠지 ②로그 열람 탭만 추가할지 ③동호회처럼 수동 실시로 바꿀지 — 어디까지 적용할까요? 학교는 자동 유지가 맞나요?"

### C2. 회원/학생 관리 화면 [ ]
동호회 변경(`a86ed62` 등):
- "선수 관리" → "회원 관리" 리네임(학교는 "학생 관리" 유지).
- **연생(출생연도) 텍스트 입력 + 2자리 자동 변환**(94→1994, 01→2001).
- **역할 뱃지 명확화**(방장/관리자/일반/미연동 현재 상태 표시 + 승격/강등 링크).
- **레거시 "코드 초기화"(PIN) 제거**.
- **관련 파일(club)**: `src/components/league/admin/AdminStudentManage.tsx`.
- **학교 적용 판단**: 연생 입력은 동호회 전용일 수 있음(학교는 학년으로 나이 갈음). **"코드 초기화" 제거는 학교에 적용 금지** — 학교는 개인 코드(PIN)를 실제로 사용함. 역할 뱃지 명확화는 학교 권한 모델(교사/기록원)에 맞게 검토.
- **확인 질문**: "학교 학생 관리에 연생 입력이 필요할까요? 역할 뱃지 표시만 학교 권한 모델에 맞춰 다듬을까요? (PIN 관련은 그대로 유지)"

### C3. 시즌 관리 — 열람 강화 / 복귀 제거 [ ]
- **과거 시즌 '복귀' 기능 제거**(시즌 간 RP 오염 버그) + **'열람' 강화**(닉네임 검색, 시즌 내 순위·티어·승률·최장연승·최근5폼·상대전적).
- 중복 스냅샷 정리(dedupe + unique index).
- **관련 파일(club)**: `src/components/league/SeasonSummary.tsx`, `admin/SeasonManagePanel.tsx`, `src/lib/league-store.ts`(changeViewSeason dedupe), `db/migrations/*dedupe_season_standings.sql`.
- **학교 적용 판단**: 학교에도 동일 '복귀' 버그가 있는지 먼저 확인. 열람 강화는 공통적으로 유용. 검색은 학교에선 **이름/학번** 기준으로.
- **확인 질문**: "학교 시즌에도 '복귀'가 있나요? 있으면 같은 버그라 제거+열람 강화로 갈까요?"

### C4. 복식 삭제 RP 롤백 팝업 — 선수별 표기 [ ]
- 복식 경기 삭제 미리보기가 **팀당 한 값**을 보여주던 것을 **선수별 개별 롤백값**으로 수정(표기만; 실제 롤백은 원래 정확).
- **관련 파일(club)**: `src/components/league/admin/AdminMatchRecords.tsx`.
- **학교 적용 판단**: 학교가 복식을 지원하면 동일 적용. 단식만이면 불필요.
- **확인 질문**: "학교도 복식 경기를 쓰나요? 그러면 삭제 팝업을 선수별 표기로 고칠까요?"

### C5. 글로벌 설정 저장 팝업 통일 / 매치추천 개편 [ ]
- 저장 토스트 `toast.promise`로 통일(`aade43a`), 매치추천 UI 개편.
- **관련 파일(club)**: `admin/AdminSettings.tsx`, `src/components/league/MatchRecommend.tsx`.
- **학교 적용 판단**: 학교도 `42a60c3`에서 매치추천을 개편함 → **차이만** 비교해 보강.
- **확인 질문**: "학교 매치추천/저장 팝업은 이미 개편됨 — 동호회와 diff 떠서 부족분만 채울까요?"

## D. 적용하지 않는(동호회 전용) 변경 — 참고용

학교에 **이식하지 말 것**(도메인 불일치). 혹시 원하면 사용자가 명시적으로 요청할 때만:
- **화면 잠금(LockGate) 전면 제거**(`a6d968a`) — 학교는 키오스크 잠금 유지.
- **개인 코드(PIN)·StudentCardSettings·player_secrets 제거**(`2026-06-25_drop_player_secrets`) — 학교는 PIN 사용.
- **일반 회원 자율 참가/온보딩·멤버 승격·강등·레벨 체계**(`e400336`, `a86ed62`) — 학교 무관.
- **강등 보호막 제거** — 학교 정책에 따라 별도 판단.
- **클럽 용어 전환**(학교→동호회 명칭, `08df22a`) — 반대 방향이므로 적용 금지.

## E. 권장 진행 순서 (UX 임팩트 ↓)

1. **B1** 경기 결과 모달(설명 토글·한글화·스크롤) — 사용자가 가장 자주 보는 화면.
2. **B2** 나의 기록(점수 전략 가이드·전적 더보기) — 능동적 참여 유도.
3. **B3** 리더보드 필터 접이식+다중선택.
4. **C1** 휴면 감점: 최소 **티어별 버그 수정 + 로그 열람**(자동 유지 가정).
5. **C2/C3/C4** 관리자 디테일.
6. **B4** 헤더 정리.
7. **A1** 테마 5종 확장(원할 경우).

각 단계 진입 전 **해당 항목의 "확인 질문"을 사용자에게 먼저** 던지고, 답을 받은 뒤 구현→검증.
