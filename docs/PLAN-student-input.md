# PLAN — 학생 직접입력 (QR)

## 결정 (2026-10-02)
- 이름: 점수입력판(교사 버튼·학생 화면 모두). 공개 순위표는 보기 전용 그대로, 점수입력판은 별도 열쇠 링크.
- 학생이 QR로 로그인 없이 결과 입력 → 바로 반영, 교사는 되돌리기만.
- 기각: 교사 승인제(손 늘어남), 양팀 확인(학생 막힘).
- 9/15 "안 함"(PLAN-post-launch 3-4)을 뒤집음.

## 장난 막기
- 기본 꺼짐, 교사가 켤 때만 QR. 그날만 유효. [새 QR] = 옛 QR 무효.
- 대기열에 있는 경기만 입력 가능(새 경기 생성 불가).

## 수파베이스 한도
- 학생 화면은 실시간 구독 안 함. 열 때·[새로고침]·입력 직후·화면 다시 볼 때만 1회 조회. 자동 반복 조회 없음.
- 교사 태블릿만 실시간 → 학생 입력이 자동으로 뜸.
- 학생 화면은 리그 스토어(구독 포함)를 불러오지 않는 별도 가벼운 페이지.

## 끝 기준
1. 교사 [학생 입력 켜기] → QR → 폰에서 로그인 없이 대기열 보임
2. 폰 입력 → 태블릿 순위 반영, 교사 되돌리기 → 지워짐
3. 끄기/[새 QR] 후 옛 QR = "입력이 닫혔어요", 기존 리그 그대로

## 계산 방식 (2026-10-02 D안)
- 학생은 점수만 보냄 → Edge Function `score-input`이 교사 태블릿과 **같은 계산 코드**로 RP 계산 → `record_match_by_key`로 저장.
- 버린 방법: A 교사 태블릿이 받아 처리(태블릿 꺼지면 멈춤) · B 계산을 SQL로 재작성(600줄 이식 위험) · C 학생 기기 계산(데이터·장난).
- 비교 시험 `bun scripts/parity-check.ts 3` (STRICT=1 권장): 최근 3일 실경기 1,463건 중 99.4% 일치. 어긋난 9건은 모두 경기 뒤 설정 변경(첫 승 보너스 등) — 계산 차이 아님.
