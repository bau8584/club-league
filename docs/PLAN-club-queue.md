# 동호회 대기열 — 설계 논의 정리

> 상태: **설계 중, 미착수** (2026-09-12)
> 학교에서 만든 대기열(출석 → 대진 뽑기 → 줄 → 결과)을 동호회 경기 탭에 올린다.
> 학교와 같은 것은 같게 두고, **달라야 하는 것만** 이 문서에 적는다.
> 계산기·프리셋·큐 구조는 [PLAN-match-assignment.md](PLAN-match-assignment.md)가 다룬다.

## 지금 동호회 경기 탭

카드 순서: [결과 입력 버튼] → [매치 추천] → [경기 예약(접힘)] → **[예약 목록]** → [결과 보기 버튼].

"예약 목록" 하나에 성격이 다른 줄이 섞여 있다.

| 종류 | 만드는 사람 | 데이터 | 줄에서 할 수 있는 것 |
|---|---|---|---|
| 인원 소집 예약 | 회원·운영진 | `player_ids`(팀 미정) | 참가 / 추가 / 알림 / 결과 입력 / 취소 |
| 매치 추천 → 예약 | 운영진 | 위와 같음 | 같음 |
| 수락된 도전장 | 회원 | 팀 확정 단식, `status = called` | 알림 / 결과 입력 / 취소 |

- **최신순** 정렬. 학교 대기열(번호순, 오래된 것이 위)과 반대.
- 번호(`seq`)와 세션(`session_id`)이 없다. 전부 "번호 없는 줄".
- `assignment_sessions`에 동호회 행이 **0개**. 그래서 대진 뽑기의 후보가 "오늘 뛴 사람 + 줄에 든 사람"으로 떨어지고, 운동 시작 직후엔 후보 0명이라 못 뽑는다.

## 결정된 것

| 항목 | 학교 | 동호회 |
|---|---|---|
| 기본 프리셋 | 다양성 | **밸런스** |
| 실력 기준 | RP | **급수 먼저, 같은 급 안에서 RP**. 급수 미지정은 최하 급 |
| 빚(지난 출석일에 덜 뛴 만큼 먼저) | 켬 | **끔** — 덜 뛴 건 늦게 온 본인 선택 |
| 강조 버튼 | [한 바퀴] | **[+1경기]** — 큐 길이를 일정하게 유지하는 운용 |
| 부제 | 6-4반 · 참석 26명 (미출전 N) | 참석 14명 (미출전 N) |
| 도전장 | 없음 | **뺀다** (2026-09-12). 보내기 버튼·배너·스토어 함수 제거. DB에 남은 `challenge` 행 정리 |

한 바퀴·+1경기·사람 바꾸기·여러 줄 빼기·명단 팝업은 **학교와 같은 코드**를 쓴다.

## 달라야 하는 것 — 아직 정할 것 포함

### 1. 출석 = "오늘 온 사람"

반이 없다. 회원 전체(모멘텀 41명)에서 오늘 온 사람을 켠다.

- 학교 명단 팝업은 "반 고르면 전원 출석, 안 온 애만 뺀다". 동호회는 **반대** — 기본은 아무도 없고, 온 사람만 켠다.
- 오늘 이미 경기한 사람은 자동으로 켜져 있다 (`today-players.ts`가 이미 뽑는다).
- 늦게 온 사람 추가가 잦다. **저장해도 팝업이 안 닫힌다** (학교는 저장 = 닫힘).
- 세션은 리그당 한 행(주인 없음). 코드가 이미 지원한다 (`apiFetchAssignmentSession`의 `ownerId = null` 경로).

**미정 — 로그인한 사람을 자동으로 잡을 것인가.**

| | A. 운영진 체크 + 오늘 경기한 사람 자동 | B. A + 앱을 열면 "온 것 같아요" 후보 표시 |
|---|---|---|
| DB 변경 | 없음 | `players.last_seen_at` 추가 + 앱 열 때 갱신 |
| 오해 | 없음 | 집에서 열어 본 사람도 후보에 뜬다 → 자동 확정은 못 하고 표시까지만 |
| 추천 | **A로 시작**, 써 보고 B 판단 | |

### 2. 예약 목록 → 대기열 카드

예약 목록 카드를 학교와 같은 대기열 카드로 **교체**한다. 큐 하나에 입력 경로 여러 개 — 회원 예약, 운영진 소집, 대진 뽑기가 한 목록에 번호 순.

- **팀 미정 줄**(소집 예약)은 기존 버튼을 유지한다: 참가 / 추가 / 알림 / 취소. 연필(사람 바꾸기)은 팀 확정 줄에만.
- **회원 화면**(관리자 아님)의 줄에도 참가·알림은 남는다. 학교의 회원 화면은 "목록만"인데 동호회는 회원이 줄을 만드는 쪽이다.
- 줄을 누르면 **결과 입력 팝업**(`openResultInput`). 학교처럼 "폼이 더러우면 확인"은 해당 없다.
- 정렬은 번호 없는 줄이라 **만든 순서(오래된 것이 위)**. 지금 회원들이 보는 최신순과 뒤집힌다 — 대기열이면 오래된 것이 위가 맞다.
- 예약 폼과 매치 추천은 그대로 두되 대기열 카드 **아래**로.

### 3. 세션 시작과 지난 예약

[새로 시작]은 세션 줄 + 내가 만든 세션 밖 줄만 지운다. 회원이 만든 예약은 살아남는다 — 의도대로다.
다만 **어제 예약도 살아남는다.** 지금도 있는 문제. 세션 시작 때 "N시간 지난 예약 M건도 정리할까요"를 묻는 정도로 시작한다. 자동 삭제는 안 한다.

### 4. `called`의 뜻

학교에서 `called` = 호출됨(코트로 입장). 도전장 수락도 `called`였다. 도전장을 빼면 동호회에서 `called`는 쓰이지 않는다. 대기열은 waiting·called를 다 보여 주므로 화면 문제는 없다. 그대로 둔다.

## 버그 후보 (합칠 때 확인)

1. 응답 없는 도전장이 `challenge`로 영구히 남아 중복 검사에 걸린다 (모멘텀 7/25 상구→쉬라몬 1건). 도전장을 빼면서 같이 정리.
2. 동호회 세션이 없으면 후보 0명. → 1번 출석이 전제.
3. 명단 팝업의 반 로직이 동호회에서 `singleClass` 경로로 떨어져 **41명 전원 출석**으로 뜬다. → 동호회는 기본값 뒤집기.
4. 팀 미정 줄에 연필을 붙이면 `player_a_id`가 없어 깨진다. → 팀 확정 줄에만.
5. 회원 화면 대기열이 "목록만"이라 참가·알림이 사라진다. → 동호회 회원 줄에 버튼 유지.

## 만들지 않는 것

- **로그인 = 출석 자동 확정** — 집에서 열어 본 사람이 출석된다. 후보 표시(B)까지만.
- **코트 수 설정** — 이미 폐기 ([PLAN-match-assignment.md](PLAN-match-assignment.md)).
- **큐 자동 보충** — 이미 폐기.
- **지난 예약 자동 삭제** — 묻고 지운다.

## 순서

1. 도전장 제거 + DB 잔여 행 정리 (대기열과 무관, 먼저)
2. 동호회 세션 = "오늘 참석" 명단 팝업 (A안)
3. 예약 목록 카드 → 대기열 카드 교체 (팀 미정 줄 버튼 유지, 회원 화면 버튼 유지)
4. 세션 시작 때 지난 예약 정리 물어보기

2~3이 반나절. 1은 한 시간.
