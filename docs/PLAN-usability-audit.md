## 한 줄 결론
**선생님 37%가 명단까지 넣고 첫 경기에서 멈춘다.** 첫 수업만 넘기면 매주 꾸준히 쓴다(42~50개 리그).
그래서 1순위는 "명단 → 첫 경기"를 이어 주는 것, 2순위는 수업 중 데이터가 꼬이거나 사라질 수 있는 구멍 막기.

### 묶음 2. 명단 → 첫 경기 이어 주기 — 상 [데이터 근거 가장 셈]
- 명단 저장 후 화면이 학생 관리에 멈춤, "이제 첫 경기" 안내 없음 (AdminStudentManage.tsx:281-297).
- 학생 넣기를 리그 만드는 흐름 안으로 (24%가 학생 0명).
- 경기장 첫 화면의 두 길(대기열 / 바로 입력) 중 하나를 고르게 함 → 첫 수업은 하나로 안내.
- 지금 첫 경기까지 약 17~20번 누름 + 결정 5개.

### 묶음 3. 매 수업 손 줄이기 — 중
- 하루 넘은 '대기' 줄 자동 정리.
- 반이 하나인 리그는 다음 주에도 새 수업으로 안 열림 → 지난주 결석생이 계속 빠짐 (session-today.ts:20-27).
- 운영 방식을 매 수업 다시 고름, 자동 채우기가 수업 끝에 꺼짐.
- 점수입력판 창에 "닫기"가 둘 — 큰 [닫기]는 학생 QR을 막아 버림 (ScoreInputDialog.tsx:63·96).
- 방금 넣은 결과를 고치려면 관리자 탭 → 메뉴 → 기록 관리 3단계. 교사 경기장엔 "오늘 경기 결과"가 없음.

### 묶음 4. 화면 읽히게 — 중 [화면 확인 일부]
- 확인함: 점수판 두 자리(11)가 되면 숫자가 [−] 버튼에 겹침. 태블릿 가로에서 고르기 화면이 가운데 좁은 칼럼(가로의 45%)에 갇힘. 결과 창 VICTORY·DEFEAT·WINNER·LOSER 영어, 9px 글씨.
- 코드 근거: 밝은 테마에 어두운 테마용 노랑·보라 글씨가 남아 대비 1.2~2.5:1 (과거 시즌 경고 띠는 거의 안 보임, class.$classId.tsx:579·586). 12px 이하 글씨가 69%.
- 대기열 [점수 넣기]가 가장 많이 누르는데 가장 작음(32px·11px, MatchQueue.tsx:547). × 는 모양 그대로, 누름 영역만 넓힘(2026-10-12 결정 유지).
- 같은 말 통일: 티어/등급, 랭킹/순위표, 결과 입력/점수 넣기/경기 기록. 로그인 화면 "수파베이스 통합 보안 소셜 로그인" 삭제.
